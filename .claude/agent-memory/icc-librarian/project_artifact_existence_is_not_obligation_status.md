**Two failure modes, opposite directions, one debt. Both are about
inferring an item's STATUS from its most visible surface instead of its
content.** Filed as `ARCHITECTURE.md` **DL-058**, 2026-08-17, discharging
half of tail debt #7 (crates.io).

**Why:** tail debt #7 had two halves. The first — *"crate-name
availability is still unchecked by anyone"* — sat unchecked across **six
days and seven dated blocks in two documents**, not because checking was
hard (five HTTP requests) but because ***"unchecked" is a stable,
safe-sounding status that costs nothing to copy forward.*** The second
half then failed the opposite way: a file named
`THIRD_PARTY_LICENSES.md` appeared at the repo root, and discharging on
that would have been wrong — it **is** genuine `cargo-about` output, and
it named **four crates at `0.0.1`** against a **five-crate, `0.1.0`**
workspace, with `about.toml` carrying no `clarify` block for the fifth,
so **regenerating would have emitted the generic SPDX MIT placeholder**
(*"Copyright (c) `<year>` `<copyright holders>`"*) — which `about.toml`'s
own comment calls *"worse than publishing nothing."*

**How to apply:**

- **Never mark an item discharged from a filename, a path, or a
  directory listing.** Open it. The dispatch that carried this one said
  *"I confirmed the path exists; I did not read it"* and told the
  librarian not to take its word — **that instruction paid for itself.**
- **A generated file is a claim about a tree AT THE MOMENT OF
  GENERATION.** It does not become malformed when the tree moves on; it
  becomes **quietly wrong while staying well-formed and confident.**
  Check its emitted data (versions, member lists) against the live
  manifest, not its header banner. `[[iccce-stale-citation-worse-than-stale-number]]`
  is the same mechanism — the right name at the right path invites the
  reader to accept the destination.
- **★ A generation rule needs a REGENERATION TRIGGER to be complete.**
  `LEGAL.md` §1 says *"generated by `cargo-about`, never hand-written"* —
  a rule about **how**, silent on **when**. It was fully honoured and
  still produced a stale manifest. `about.toml`'s stated trigger is
  *"after ANY dependency change"*, and **adding a workspace member is
  not one** — exactly the gap `iccce-measure` fell through.
- **A crates.io name check is a DATED OBSERVATION WITH AN EXPIRY, never
  a reservation.** crates.io has no reservation mechanism; names go to
  the first successful publish. *"The names were checked"* is the shape
  of sentence that stays true, goes stale, and stays load-bearing — so
  **the date is part of the claim** and it must be **re-run immediately
  before any first publish**. It **authorises nothing**: rule 9 and
  DL-009 are untouched by a free name.
- **Check the query's population, not just its results.** The check used
  DL-009's name list of 2026-08-11 and so covered **five of six**
  candidate names — `iccce-measure` was never queried, and `iccce` (a
  facade name that is not a workspace member) was. **A stale enumeration
  copied into a query returns clean results and looks complete**
  — `[[iccce-count-from-a-sample-is-not-the-population]]`.
- **Not everything true belongs in the ledger.** No NC row and no §7.20
  status pass was opened: `NUMERIC_CLAIMS.md`'s subject is tolerances and
  measured errors, an HTTP response body carries no evidence class, and
  **opening a §7 pass would have moved an integer §7 itself tracks** for
  an item it has never carried. Recorded as a judgement so it can be
  overturned by argument rather than discovered as an absence.
